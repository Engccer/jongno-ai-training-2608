지금 바로

1. EVPN 신청

자택에서 나이스·K-에듀파인·교데통에 접속하려면 교육청 원격업무지원서비스(EVPN)가 있어야 합니다. 학교 부서장 승인을 거쳐 며칠이 걸리므로 이 안내를 받으시는 즉시 신청해 주세요. 8월 31일 2회기 전까지 승인이 나야 합니다.

신청 방법

  1. 나이스에서 [기본메뉴] > [원격업무지원서비스] > [원격업무지원서비스(eVPN)] 으로 들어갑니다.
  2. 신청서에 다음을 적습니다. - 사용기간: 최대 6개월까지 가능하며, 시작일자는 신청 당일로 잡습니다. - 접속그룹: 업무포털. - VPN 전용 비밀번호: 숫자·영문·특수문자를 조합해 9자 이상. 아이디와 같게 쓸 수 없습니다. 나이스 비밀번호와 별개이므로 따로 기록해 두세요. - 보안서약서 동의와 요청사유.
  3. 신청 후 학교 부서장(정보보안 담당) 승인을 받아야 사용할 수 있습니다. 담당 선생님께 승인을 요청해 주세요.

확인 방법

승인이 나면 브라우저로 아래 주소에 접속해 로그인이 되는지 확인합니다.

https://evpn.sen.go.kr

서울 외 시도는 evpn. 뒤의 교육청 도메인이 다릅니다(대구 evpn.dge.go.kr, 충남 evpn.cne.go.kr, 부산 evpn.pen.go.kr, 인천 evpn.ice.go.kr 형태).

로그인하면 상단에 다운로드와 Run VPN 버튼이 생깁니다. 이 컴퓨터에서 처음 쓰시는 것이면 다운로드로 클라이언트를 설치하고, Run VPN을 눌러 뜨는 별도 창에서 같은 아이디와 VPN 비밀번호로 한 번 더 로그인합니다. 상단 상태가 Installed, Running, Connected 모두 Yes가 되면 연결된 것입니다.

이미 EVPN을 쓰고 계시면 신청은 건너뛰고 위 확인만 해 주세요. 사용기간이 만료됐으면 나이스에서 다시 신청하셔야 합니다.

여는 말

앞선 13시간과 무엇이 다른가

  • 앞선 13시간: 프롬프트 엔지니어링, AI 윤리, 정보 접근과 활용. AI에게 질문하고 좋은 답변을 얻어내는 법.
  • 남은 9시간: AI에게 내 컴퓨터의 파일과 폴더를 다루게 하고, 학교 업무 시스템을 대신 조작하게 만드는 법.

챗봇과 에이전트의 결정적인 차이는 결과물이 남는 위치임.

  • 챗봇: 대화창에 텍스트 답변을 보여주는 데서 멈춤. 공문 요약을 요청하면 화면에 요약글이 뜨지만, 그 내용을 한글 문서나 파일로 옮기는 일은 여전히 사용자 몫임.
  • 에이전트: 지정된 폴더에 직접 들어가 파일을 읽고, 문서를 편집하고, 결과 파일(.hwpx, .md, .csv 등)을 폴더에 저장함. 탐색기를 열어 보면 파일이 실제로 생성되어 있음.

이 차이가 학교 업무에서 중요한 이유:

  • 교사의 행정 업무는 화면 위의 대화로 끝나지 않음.
  • 공문을 열어 검토하고, 한글 서식을 채워 결재를 올리고, 나이스나 교무업무시스템에서 신청과 제출을 마쳐야 비로소 끝남.
  • 챗봇이 돕는 구간은 그 앞단의 초안 작성까지임. 실제 문서를 만들고 시스템을 조작하는 그다음 구간 전체가 이 9시간의 대상임.

4회기 커리큘럼의 흐름

  • 1회기, 작업 환경 셋업: Claude Desktop 앱(Code 탭)과 Claude Code CLI 환경을 구축하고, 작업 폴더 지정과 음성 요약 루프를 완성함.
  • 2회기, 행정업무 자동화 기본: 업무 자동화 스킬을 설치하고, Chrome 확장과 연동해 나이스·K-에듀파인·교데통에 접속함.
  • 3회기, 행정업무 자동화 심화: K-에듀파인의 결재 대기 공문을 추출해 음성으로 확인하고, 나이스 복무 신청을 반자동으로 처리함.
  • 4회기, 수업과 평가: 수업·평가 자료를 제작하고, 각자의 직무에 맞춘 전용 스킬을 직접 만듦.

환경 구축, 시스템 접속, 실무 조작, 맞춤형 창작의 네 단계임. 앞 회기의 환경이 갖춰지지 않으면 다음 단계 실습이 성립하지 않으므로, 오늘의 설치와 설정이 전체 과정의 밑바탕임.

1. EVPN 신청 상태

  • 필요한 이유: 자택에서 나이스·K-에듀파인·교데통에 접속하려면 교육청 원격업무지원서비스(EVPN) 승인이 필요함.
  • 소요 기간: 부서장 결재를 거치므로 며칠이 걸림. 2회기(8/31) 실습 전까지 승인이 완료되어야 함.
  • 신청 경로: 나이스의 [기본메뉴] > [원격업무지원서비스]. 아직 신청 전이면 오늘 회기가 끝나는 즉시 신청함.
  • 입력값: 사용기간은 최대(6개월), 시작일자는 신청 당일. VPN 전용 비밀번호를 설정하고 보안서약서에 동의함.

2~6. 계정과 설치

  1. Claude Pro 계정 로그인: 센터가 지원하는 Pro 계정임. 무료 계정에서는 Desktop 앱에 Code 탭 자체가 나타나지 않으므로 플랜 확인이 가장 먼저임.
  2. Claude Desktop 앱 설치: 최신 버전으로 설치되어 있는지 확인함.
  3. Git 설치 여부: 아직 설치 전이면 따라 하기 1에서 함께 진행함.
  4. Node.js와 Python 설치 여부: 명령줄 도구 실행에 필요한 런타임임.
  5. 홈 디렉터리 연습 폴더: 본인 업무와 관련된 공문 PDF 1개와 한글 문서(.hwpx 또는 .hwp) 1개가 들어 있어야 함.

두 도구를 함께 쓰는 이유

이 과정에서는 Claude Desktop 앱(Code 탭)과 Claude Code CLI(터미널) 두 가지를 모두 셋업함. 굳이 둘을 함께 다루는 이유는 각 도구의 쓰임새와 강점이 다르기 때문임.

구분 Claude Desktop 앱 (Code 탭) Claude Code CLI (터미널)
주요 쓰임새 긴 호흡의 작업, 생성물(아티팩트) 실시간 미리보기, 사용량 점검, 프로젝트 단위 작업 폴더 하나에서 짧게 끝나는 단발성 작업, 여러 폴더를 오가는 작업, 여러 터미널을 띄운 병렬 작업
실행 방법 앱 실행 후 '폴더 선택' 버튼으로 작업 폴더 지정 파일 탐색기에서 작업할 폴더를 열고 Alt+T로 터미널을 띄운 뒤 claude 실행
스크린 리더 조작 웹 탐색 명령과 Tab 이동이 그대로 통함. 대신 편집창·버튼·텍스트 영역을 오갈 때 가상 커서 전환이 필요함 프롬프트 입력과 키패드 리뷰 탐색 중심임. 조작 체계가 단순한 대신 키패드 탐색에 익숙해야 함
체감 성능 구동과 업데이트에 시간이 다소 걸림 메모장처럼 가볍게 열고 닫음
  • 터미널이 편한 경우: 터미널을 띄운 바로 그 폴더만 작업 범위(컨텍스트)로 잡힘. 파일 탐색기에서 하위 폴더로 세분화해 자료를 관리한다면 이 방식이 군더더기가 없음.
  • 앱이 편한 경우: 웹 결과물을 미리보기로 직접 확인해야 하거나, 하나의 프로젝트를 긴 호흡으로 다듬어 갈 때.

'Code'라는 이름 때문에 프로그래밍 전용 도구로 생각하기 쉽지만, 실제로는 컴퓨터로 할 수 있는 일상 업무 대부분을 처리함. 문서 작성, 파일 변환, 웹 검색, 시스템 설정 변경까지 코딩 지식 없이 자연어 대화만으로 제어함.

따라 하기 1: Desktop 앱 Code 탭 셋업

오늘 실습 중 손이 가장 많이 가는 단계임. 순서를 건너뛰지 않음.

  1. Code 탭 이동: Claude Desktop 앱을 실행하고, 좌측 상단 탭 영역에서 Code 탭 버튼을 눌러 이동.
  2. Git 설치 안내 확인: 처음 진입하면 Git 설치 안내 대화상자가 자동으로 뜸. 대화상자에서 Git 다운로드 버튼을 누름. - 나중에를 선택하면 Git 연동이 되지 않아 다음 단계가 막힘. 반드시 Git 다운로드를 선택함. - 사전 준비에서 이미 Git을 설치했으면 이 대화상자가 나타나지 않을 수 있음. 그러면 4번으로 바로 이동.
  3. Git 설치 진행: 내려받은 설치 파일(Git-x.x.x-64-bit.exe)을 실행하고, 설치 마법사의 모든 화면에서 기본 설정 그대로 Next 또는 Install을 눌러 끝까지 설치.

  4. 설치 확인 요청: Code 탭으로 돌아와 하단 프롬프트 입력창에 확인을 요청.

    Git 설치를 마쳤는데 제대로 설치된 것인지 확인해 줘.

  5. PowerShell 실행 권한 허용: Claude가 설치 상태를 확인하려고 PowerShell 명령 실행 권한을 요청함. 거부, 한 번만 허용, 항상 허용 세 버튼 중 항상 허용을 선택. 이후 동일한 명령에는 다시 묻지 않음.

  6. 환경 변수 자동 설정: Git이 설치되어 있어도 Claude가 bash.exe 경로를 찾지 못하면 CLAUDE_CODE_GIT_BASH_PATH 환경 변수 설정 안내가 뜸. 옵션 1(PowerShell로 영구 설정)과 옵션 2(Windows GUI 설정)가 제시되면, 시스템 설정 창을 직접 열지 않고 입력창에 한 줄 적음.
    옵션 1로 네가 바로 설정해 줘.

Claude가 PowerShell 명령으로 환경 변수를 설정함. 7. 앱 완전 종료 후 재실행: 설정이 끝나면 앱을 완전히 닫고 다시 실행. Alt+F4로 창을 닫은 뒤, 작업 표시줄 알림 영역(트레이)의 Claude 아이콘에서 팝업 키(Shift+F10)를 눌러 종료를 선택하면 확실함. - 환경 변수 안내가 처음부터 뜨지 않으면 Claude가 이미 설정을 마친 것이므로 그대로 진행함.

여기까지 마치면 Code 탭이 정상적으로 열림.

따라 하기 2: 폴더 지정과 첫 지시

에이전트는 지정한 폴더를 작업 범위로 삼음. 폴더를 지정해야 결과 파일이 정확한 위치에 생성됨.

  1. 작업 폴더 선택: Code 탭 프롬프트 입력창 바로 위의 폴더 선택 버튼을 누름. 파일 선택 대화상자가 열림.
  2. 연습 폴더 지정: 홈 디렉터리에 미리 만들어 둔 연습 폴더로 이동한 뒤 폴더 선택 버튼을 누름. 입력창 상단에 폴더 이름이 표시되면 지정 완료.

  3. 첫 지시 전송: 하단 입력창에 첫 지시를 입력하고 전송.

    이 폴더에 어떤 파일이 있는지 읽고 정리해 줘.

  4. 결과 확인: 연습 폴더에 넣어 둔 공문 PDF와 한글 문서를 인식하고 파일 이름과 형식을 설명하면 정상임.

샌드박스와 권한 관리

  • 작동 범위: 에이전트는 격리된 작업 영역(샌드박스) 안에서만 작동함. 지정된 작업 폴더 안에서는 자유롭게 문서를 읽고 씀.
  • 승인이 필요한 경우: 폴더 밖 시스템에 접근하거나 프로그램을 설치할 때. 승인 창이 뜨면 요청 내용을 확인하고 허용 여부를 결정함.
  • 자동 모드: 작업 폴더 안에서 반복적으로 뜨는 승인 창을 줄이는 설정임. 입력창 좌측 하단의 편집 수락 풀다운 메뉴에서 자동을 선택하고, 확인 창에서 자동 모드 활성화를 누름. 지정한 작업 폴더 내부에만 적용되고 폴더 외부 시스템 영역에는 적용되지 않음.

참고: Pro 계정인데도 '자동' 모드가 메뉴에 보이지 않으면 앱이 구버전임. 좌측 상단 메뉴의 업데이트 확인으로 최신 버전을 받음.

파일 경로를 정확히 전달하는 요령

  • 방법: 파일 탐색기에서 대상 파일을 선택하고 Ctrl+Shift+C를 누르면 전체 경로가 클립보드에 복사됨. 이를 입력창에 붙여넣고 지시함.
  • 효과: 폴더에 파일이 여러 개일 때 엉뚱한 파일을 건드리지 않음.
  • 적용 범위: 이후 세 회기 내내 씀.

따라 하기 3: 터미널 CLI 환경 셋업

같은 Claude 에이전트를 터미널에서 가볍게 구동하는 절차임.

  1. 작업 폴더 열기: 파일 탐색기에서 홈 디렉터리의 연습 폴더로 들어감.
  2. 터미널 열기: 파일이 선택되지 않은 빈 영역에서 팝업 키(또는 Shift+F10)를 눌러 폴더 컨텍스트 메뉴를 열고 터미널에서 열기를 선택. 단축키는 Alt+T.

  3. Claude Code 실행: PowerShell 터미널이 열리면 다음을 입력하고 Enter.

    claude

  4. 로그인 인증: 처음 실행하면 브라우저 인증 창이 열림. Claude 계정으로 로그인을 마치고 터미널로 돌아옴.

  5. 동작 확인: 프롬프트가 나타나면 간단한 지시를 보내 응답이 출력되는지 확인.

터미널을 연 바로 그 폴더가 자동으로 작업 범위가 되므로, 앱처럼 폴더를 별도로 지정하지 않음.

따라 하기 4: 스크린 리더 모드 켜기

  • 문제: 터미널 화면에는 테두리 선이나 진행 애니메이션 같은 장식 문자가 포함되어 있어, 키패드로 탐색할 때 불필요한 음성이 많이 낭독됨.
  • 해결: Claude Code가 이를 평문으로 전환해 주는 전용 스크린 리더 모드(axScreenReader)를 기본 제공함.

터미널 프롬프트에 한 줄 적음.

스크린 리더 모드 켜 줘.
  • Claude가 내부 설정을 감지해 즉시 활성화함.
  • 전역(Global) 설정으로 저장되므로, 한 번 켜 두면 터미널을 다시 열거나 다른 폴더에서 작업할 때도 유지됨.
  • 설정 전후로 키패드 탐색을 해 보아 장식 문자가 사라졌는지 확인함.

따라 하기 5: 두 도구로 동일한 폴더 다루기

Desktop 앱과 터미널 CLI가 같은 컴퓨터의 같은 폴더를 다룬다는 것을 확인하는 단계임.

  1. 터미널에서 파일 목록 조회: 앱과 터미널이 모두 연습 폴더를 작업 범위로 잡은 상태에서, 터미널 프롬프트에 따라 하기 2와 동일한 지시를 보냄.

    이 폴더에 어떤 파일이 있는지 읽고 정리해 줘.

  2. 결과 비교: Desktop 앱에서 확인했던 것과 동일한 파일 목록이 출력되는지 확인.

  3. 터미널에서 파일 생성: 터미널에 다음과 같이 지시해 새 문서를 만듦.

    오늘 배운 핵심 내용을 세 줄로 정리해서 1회기 정리.md 파일로 저장해 줘.

  4. 탐색기에서 생성 파일 확인: 파일 탐색기에서 연습 폴더를 열어 1회기 정리.md가 실제로 생성되었는지 확인. 챗봇과 에이전트의 차이를 직접 확인하는 단계임.

두 도구는 동일한 로컬 파일 시스템을 제어함. 한쪽에서 만든 파일을 다른 쪽에서 즉시 읽고 편집하므로, 작업의 성격과 호흡에 맞추어 편한 쪽을 고르면 됨.

따라 하기 6: 작업 결과 요약을 음성으로 듣기

  • 문제: 에이전트가 복잡한 작업을 마치면 터미널에 긴 결과 텍스트가 출력됨. 매번 키패드로 긴 화면을 훑어야 함.
  • 해결: 작업 완료 시 핵심 요약을 음성(TTS)으로 브리핑해 주는 agent-cli-tts-summary 스킬을 설치함. 이 설정 하나로 이후 세 회기의 실습 피로도가 줄어듦.
  • 비용: 기본 음성은 Windows 내장 음성 엔진을 쓰므로 별도의 API 키나 비용이 들지 않음. 더 자연스러운 음성이 필요하면 나중에 Gemini나 ElevenLabs 키를 넣을 수 있으나 오늘은 기본값으로 둠.

  1. 스킬 설치 지시: 터미널 또는 Desktop 앱 입력창에 전송.

    https://github.com/Engccer/skills-for-the-blind 의 agent-cli-tts-summary 스킬을 설치해 줘.

  2. 실행 권한 승인: 스킬 다운로드와 명령 실행 승인 대화상자가 나타나면 내용을 확인하고 허용.

  3. TTS 훅 설정 요청: 설치가 끝나면 스킬 지침에 따른 환경 설정을 지시.

    이 스킬대로 TTS 요약 루프를 설정해 줘.

  4. 자동 설정 완료: 에이전트가 종료 훅(Hook)과 스크립트 경로 설정을 자동으로 처리함. 중간에 권한 요청이 뜨면 허용.

  5. 음성 출력 테스트: 설정이 끝나면 간단한 작업을 지시.

    지금 이 폴더에 있는 파일 개수를 세어 줘.

  6. 음성 브리핑 확인: 작업이 끝나는 순간 요약이 음성으로 흘러나오는지 확인.

음성이 재생되면 오늘 1회기 목표에 도달한 것임.

과제 및 2회기 안내

2회기(8/31) 실습을 위해 다섯 가지를 갖춤. 하나라도 빠지면 다음 회기 시스템 접속 실습이 진행되지 않음.

  1. EVPN 승인 및 접속 확인: 승인이 완료되면 자택 PC에서 https://evpn.sen.go.kr에 접속해 웹 로그인과 클라이언트 연결을 확인함. 서울 외 지역은 해당 시도 교육청 EVPN 주소를 씀.
  2. Claude in Chrome 확장 프로그램 설치: 브라우저 기반 학교 행정 시스템을 제어하는 데 필요함.
  3. PowerShell 7 설치: K-에듀파인의 문서 팝업 창을 제어할 때 씀.
  4. Gemini API 키 발급: Google AI Studio에서 무료 티어로 발급함.
  5. 교육행정 전자서명(EPKI) 인증서 준비: 실습 노트북에 본인 인증서가 등록되어 있는지 확인함.

필요한 프로그램 설치나 상태 확인은 오늘 셋업한 에이전트에게 자연어로 맡기는 편이 빠름.

PowerShell 7이 설치되어 있는지 확인하고, 없으면 설치해 줘.

이렇게 에이전트에게 설정을 직접 시켜 보는 과정 자체가 AI와 함께 일하는 연습임.

  • 실습 도구: Claude Desktop 앱(Code 탭), Claude Code CLI, Claude in Chrome 확장, PowerShell 7

이번 시간의 목표

  • 작업 결과 요약을 음성(TTS)으로 듣는 환경을 완성함.
  • 업무 자동화 스킬 여덟 개를 설치함.
  • EVPN으로 교육청 내부망에 연결하고 업무포털에 로그인함.
  • 나이스·K-에듀파인·교데통 세 시스템에 에이전트로 진입함.

따라 하기 6: 작업 결과 요약을 음성으로 듣기

  • 문제: 에이전트가 작업을 마치면 긴 결과 텍스트가 화면에 남음. 매번 키패드로 훑어야 무엇을 했는지 알 수 있음.
  • 해결: 작업이 끝나는 순간 핵심 요약을 음성으로 브리핑하는 agent-cli-tts-summary 스킬을 설치함.
  • 비용: 기본 음성은 Windows 내장 음성 엔진을 쓰므로 API 키도 비용도 들지 않음. 오늘은 기본값으로 둠.

오늘 이 설정을 먼저 하는 이유는 이후 실습의 성격 때문임. 세 시스템에 접속하면 에이전트가 화면을 읽어 목록과 항목을 길게 보고함. 그 결과를 매번 화면에서 찾아 읽는 것과 요약을 귀로 듣는 것은 실습 속도가 다름.

  1. 스킬 설치 지시: 터미널 또는 Desktop 앱 입력창에 전송.

    https://github.com/Engccer/skills-for-the-blind 의 agent-cli-tts-summary 스킬을 설치해 줘.

  2. 실행 권한 승인: 스킬 다운로드와 명령 실행 승인 대화상자가 뜨면 내용을 확인하고 허용.

  3. TTS 훅 설정 요청: 설치가 끝나면 스킬 지침에 따른 환경 설정을 지시.

    이 스킬대로 TTS 요약 루프를 설정해 줘.

  4. 자동 설정 완료: 에이전트가 종료 훅(Hook)과 스크립트 경로 설정을 처리함. 중간에 권한 요청이 뜨면 허용.

  5. 음성 출력 테스트: 설정이 끝나면 간단한 작업을 지시.

    지금 이 폴더에 있는 파일 개수를 세어 줘.

  6. 음성 브리핑 확인: 작업이 끝나는 순간 요약이 음성으로 흘러나오는지 확인.

음성이 재생되면 1회기 목표까지 완결된 것임.

참고: 음성이 나오지 않으면 훅 설정 파일의 경로가 어긋난 것임. 설정한 TTS 훅이 왜 안 도는지 확인하고 고쳐 줘라고 그대로 지시하면 에이전트가 설정 파일을 읽어 진단함.

규칙 파일과 스킬

  • 규칙 파일: 늘 지켜야 할 규칙을 적어 두는 파일임. 이름은 CLAUDE.md이고 다른 에이전트에서는 AGENTS.md라고 부름. "문서는 항상 마크다운으로 저장해라" 같은 규칙을 한 번 적어 두면 매번 말하지 않아도 됨.
  • 스킬: 반복 작업의 절차를 묶어 둔 파일임. 한 번 만들어 두면 이름만 불러 재사용함. 직접 만들 수도 있고 남이 공개한 것을 설치할 수도 있음.

오늘은 공개된 것을 설치함. 직접 만드는 일은 4회기에서 다룸.

왜 브라우저 조작으로 도는가

세 시스템은 외부 프로그램이 데이터를 주고받을 통로를 열어 두지 않았음. 그래서 이 스킬들은 사람이 하던 것과 같은 방식으로 작동함. 브라우저를 열고, 메뉴를 찾아 누르고, 화면을 읽고, 값을 채움. Claude in Chrome 확장이 그 통로임.

K-에듀파인의 결재·기안 문서 창은 사정이 하나 더 있음. 그 창은 브라우저 탭이 아니라 별도의 프로그램 창이고 내부는 옛 인터넷 익스플로러로 그려짐. 브라우저 도구로는 닿지 않으므로 PowerShell 7을 거쳐 창 안을 직접 읽고 조작함. 사전 준비에 PowerShell 7이 들어 있던 이유가 이것임.

스킬에 쌓인 것은 우회 지식임

세 시스템의 화면은 접근성이 고르지 않음.

  • 커스텀 드롭다운은 스크린 리더가 목록으로 인식하지 못해 값을 직접 넣을 수 없음.
  • 날짜 필드는 달력 아이콘으로만 열리고, 시작일을 바꾸면 종료일이 따라 움직임.
  • 알림은 조작 직후가 아니라 몇 초 뒤에 나타남.
  • 완결 처리된 건에서는 눌리지 않는 버튼이 있음.

이런 화면을 손으로 다루려면 매번 같은 우회를 다시 찾아야 함. 스킬에 적힌 것이 그 우회 지식임. 어느 드롭다운이 클릭으로만 열리는지, 어느 알림이 몇 초 뒤에 뜨는지가 화면별로 기록돼 있음. 강사가 실제 업무에서 밟은 시행착오가 그대로 쌓인 것이고, 오늘 설치한 것은 그 기록임.

따라 하기 8: EVPN 접속과 업무포털 로그인

학교 밖에서 내부 업무 시스템에 들어가려면 교육청 원격업무지원서비스(EVPN)를 먼저 거쳐야 함.

  • EVPN이 필요한 시스템: 업무포털과 K-에듀파인. 연결 없이는 서버 응답 자체가 없어, 화면이 뜨지 않고 그냥 멈춘 것처럼 보임.
  • EVPN 없이도 되는 시스템: 나이스. 공인망에서도 서버가 응답함. 다만 업무포털을 거친 자동 로그인은 쓸 수 없어 나이스 자체 인증서 로그인을 해야 함.
  1. 웹 로그인: 브라우저로 자기 교육청 EVPN 주소에 접속해 나이스 아이디와 VPN 전용 비밀번호로 로그인. 비밀번호는 본인이 직접 넣음.
  2. 설치 안내 팝업 닫기: 첫 화면에 설치 안내 팝업이 떠 있으면 닫음. 이 팝업은 마우스 클릭을 가로채지만 키보드 탐색에는 영향이 없음.
  3. 클라이언트 로그인: 상단 Run VPN 버튼을 누르면 별도의 클라이언트 로그인 창이 뜸. 웹 로그인과는 다른 2차 인증이며, 같은 아이디와 VPN 비밀번호로 로그인하면 터널이 연결됨.
  4. 연결 확인: 페이지 상단 상태의 Installed, Running, Connected가 모두 Yes가 되면 연결된 것임.
  5. 업무포털 로그인: 자기 교육청 업무포털 주소로 이동해 인증서로 로그인. 인증서 비밀번호는 언제나 본인이 직접 넣음. 이 입력은 자동화하지 않음.

알아 둘 함정 두 가지

  • Installed No가 미설치를 뜻하지 않음: 클라이언트가 설치돼 있어도 실행 중이 아니면 No로 표시됨. Run VPN으로 클라이언트를 호출하면 Yes로 바뀜.
  • 터널이 오래 유지되지 않음: 실측에서 연결 12분 뒤에 끊긴 사례가 있음. 작업 중 화면이 갑자기 응답하지 않으면 EVPN이 끊긴 것부터 의심하고, 웹 재로그인과 Run VPN을 다시 밟음. 오늘 남은 두 시간 동안 여러 번 겪게 될 상황이므로 재연결 절차를 손에 익혀 둠.

따라 하기 9: 나이스 접속

로그인까지는 사람이 했음. 여기서부터 화면을 읽고 누르는 일을 에이전트에게 맡김.

  1. 브라우저 연결 확인: Chrome이 실행 중이고 Claude 확장에 로그인돼 있는지 확인. 처음 연결에는 시간이 걸리므로, 에이전트가 브라우저를 찾지 못한다고 하면 잠시 뒤 다시 지시함.

  2. 진입 지시: 입력창에 전송.

    나이스 스킬로 업무포털에서 나이스에 들어가 줘. 로그인은 내가 이미 해 뒀어.

  3. 자동 진입 진행: 에이전트가 업무포털 메인의 공지 팝업을 닫고 [나이스] 링크를 눌러 새 탭으로 진입함. 로그인 정보는 자동으로 넘어감.

  4. 화면 판독 요청: 나이스 메인이 뜨면 화면을 읽게 함.

    지금 화면에 무엇이 있는지 알려 줘. 좌측 메뉴에 어떤 항목이 있어?

  5. 메뉴 확인: 좌측 기본 메뉴에 복무, 외부활동, 승인사항 같은 항목이 잡히는지 확인함.

여기까지가 오늘의 나이스 목표임. 확인할 지점은 화면에 들어갔다는 사실이 아니라 화면을 에이전트가 읽어 준다는 사실임. 무엇이 어디에 있는지 스스로 훑지 않아도 되고, 필요한 메뉴를 이름으로 물어 찾아갈 수 있음.

따라 하기 10: K-에듀파인 접속

  1. 진입과 목록 판독 지시: 업무포털로 돌아가 전송.

    K-에듀파인 스킬로 K-에듀파인에 들어가서 결재대기 목록을 읽어 줘.

  2. 자동 진입 진행: 업무포털 상단의 [K-에듀파인]을 누르면 새 탭으로 진입함. 보안 프로그램 안내 페이지가 먼저 뜨면 에이전트가 넘김.

  3. 목록 확인: 문서관리 > 결재 > 결재대기로 이동해 목록을 읽음. 문서 제목, 기안 부서, 긴급 여부, 첨부 건수가 나옴.
  4. 건수 대조: 결재 대기 건수는 업무포털 메인의 K-에듀파인 문서함 위젯으로도 확인됨. 처리 전후를 대조할 때 편함.

  5. 문서 열기 지시: 목록에서 한 건을 골라 전송.

    첫 번째 문서를 열어 줘.

  6. 화면 무변화가 정상: 문서를 열어도 브라우저 화면에는 아무 변화가 없음. 새 탭도 생기지 않음. 결재 문서 창은 브라우저 밖의 별도 프로그램 창으로 뜨기 때문임. 화면이 그대로라고 실패로 오해해 다시 누르면 누른 횟수만큼 창이 중복 생성되므로 반복 클릭하지 않음.

  7. 창 확인 지시: 창이 떴는지는 에이전트에게 확인시킴.

    결재 문서 창이 떴는지 확인하고, 창 안의 문서 제목을 읽어 줘.

  8. 판독 확인: PowerShell 브리지가 창 안을 잡아 제목과 본문 일부를 읽어 주면 오늘의 K-에듀파인 목표에 도달한 것임.

6번의 무변화가 이 시스템에서 가장 헷갈리는 지점임. 화면 변화로 성공 여부를 판단할 수 없으므로, 조작 결과는 언제나 에이전트에게 물어 확인함.

따라 하기 11: 교데통 접속

교데통은 K-에듀파인의 자료집계를 대체한 데이터 취합 플랫폼임.

  • 주소가 두 개임: www.edmgr.kr은 일반 공개 포털이고, 데이터취합 메뉴가 있는 것은 시도 서브도메인이 붙은 업무용 주소 하나뿐임. 공개 포털로 들어가면 아무리 뒤져도 제출 화면이 없음.

  1. 진입 지시: 업무포털 상단 메뉴의 [교데통]으로 들어감. 창 폭이 좁으면 메뉴가 잘려 보이므로 에이전트에게 링크를 찾게 하는 편이 빠름.

    교데통 스킬로 교데통에 들어가서 제출자료 화면을 열어 줘.

  2. 팝업 두 겹 닫기: 교데통 메인에 처음 들어가면 공지 팝업이 두 겹으로 뜸. 안쪽부터 닫음. 팝업 하단의 "다시 열지 않음" 체크는 임의로 켜지 않음.

  3. 메뉴 이동: 상단 메뉴에서 데이터취합 > 제출자료로 이동.

  4. 화면 구조 판독 요청: 전송.

    지금 화면의 탭과 각 탭의 건수를 알려 줘.

  5. 탭 확인: 기관접수대기, 내담당, 제출완료, 종료, 강제종료 다섯 탭과 각각의 건수가 나오면 정상임.

목록이 비어 있어도 요청이 없는 것은 아님

기관접수대기 목록은 기관 안의 전체 직원에게 보이고, 누군가 접수하면 나머지 사람의 목록에서 사라짐. 목록이 비어 있다고 해서 학교에 온 취합 요청이 없다고 단정하지 않음. 건수가 많으면 요청자료명에 키워드를 넣고 조회하는 편이 빠름.

세 시스템 자동화의 경계

"나이스나 K-에듀파인은 자동화가 안 된다"는 말이 오래 통용됐음. 정확히 말하면 막혀 있는 것이 아니라 화면마다 우회가 필요함. 그 우회를 하나씩 알아내는 데 시간이 들 뿐이고, 알아낸 것을 스킬에 적어 두면 다음부터는 그 시간이 들지 않음.

되는 범위와 멈추는 지점은 다음과 같음.

  • 읽기와 조회는 폭넓게 됨: 목록 읽기, 상세 화면 읽기, 현황 조회, 문서 저장.
  • 폼 채우기와 검증도 됨: 복무 신청 화면의 항목을 채우고 계산된 값이 맞는지 확인하는 데까지.
  • 비가역 조작은 사람이 확인함: 상신, 문서처리, 제출, 발송은 한 번 누르면 되돌리기 어려움. 자동화는 확정 버튼 앞에서 멈추고 무엇을 하려는지 요약해 보고함.
  • 자격증명은 자동화하지 않음: 인증서 비밀번호와 VPN 비밀번호는 언제나 본인이 직접 넣음.

뒤의 두 항목은 기술의 한계가 아니라 정해 둔 선임. 되돌릴 수 없는 일은 사람이 확인하고 누름.

과제 및 3회기 안내

3회기(9/2)는 세 시스템에 들어간 다음의 실습임. 각자 실제로 처리해야 할 업무를 하나씩 가지고 옴. 예제가 아니라 실제 건이어야 함.

  1. 신청할 복무 하나: 다음 달에 올릴 연가·출장·특별휴가 가운데 하나를 정함. 지난번에 올린 같은 유형의 건이 있으면 그 내용을 확인해 둠.
  2. 확인할 결재 대기 공문 하나: 오늘 본 결재대기 목록에서 첨부가 있는 건을 하나 골라 둠.
  3. 교데통에 온 취합 요청 하나: 있으면 요청자료명을 적어 옴. 없으면 지나간 건으로 대신함.

세 시스템 접속이 오늘 안 된 사람은 3회기 전까지 접속만 다시 확인해 둠. 다음 시간은 들어간 다음의 실습이라 진입 경로가 열려 있어야 함.

3회기에서는 나이스 복무 신청을 신청 버튼 직전까지 진행하고, K-에듀파인 결재 대기 공문을 PC로 저장한 뒤 그 공문을 파싱해 음성으로 듣는 데까지 이어 붙임. 오늘 설치한 docparse·abridge·speech-toolkit 세 스킬을 거기서 함께 씀.
