지금 바로

1. EVPN 신청

자택에서 나이스·K-에듀파인·교데통에 접속하려면 교육청 원격업무지원서비스(EVPN)가 있어야 합니다. 학교 부서장 승인을 거쳐 며칠이 걸리므로 이 안내를 받으시는 즉시 신청해 주세요. 8월 31일 2회기 전까지 승인이 나야 합니다.

신청 방법

  1. 나이스에서 [기본메뉴] > [원격업무지원서비스] > [원격업무지원서비스(eVPN)] 으로 들어갑니다.
  2. 신청서에 다음을 적습니다. - 사용기간: 최대 6개월까지 가능하며, 시작일자는 신청 당일로 잡습니다. - 접속그룹: 업무포털. - VPN 전용 비밀번호: 숫자·영문·특수문자를 조합해 9자 이상. 아이디와 같게 쓸 수 없습니다. 나이스 비밀번호와 별개이므로 따로 기록해 두세요. - 보안서약서 동의와 요청사유.
  3. 신청 후 학교 부서장(정보보안 담당) 승인을 받아야 사용할 수 있습니다. 담당 선생님께 승인을 요청해 주세요.

확인 방법

승인이 나면 브라우저로 아래 주소에 접속해 로그인이 되는지 확인합니다.

https://evpn.sen.go.kr

서울 외 시도는 evpn. 뒤의 교육청 도메인이 다릅니다(대구 evpn.dge.go.kr, 충남 evpn.cne.go.kr, 부산 evpn.pen.go.kr, 인천 evpn.ice.go.kr 형태).

로그인하면 상단에 다운로드와 Run VPN 버튼이 생깁니다. 이 컴퓨터에서 처음 쓰시는 것이면 다운로드로 클라이언트를 설치하고, Run VPN을 눌러 뜨는 별도 창에서 같은 아이디와 VPN 비밀번호로 한 번 더 로그인합니다. 상단 상태가 Installed, Running, Connected 모두 Yes가 되면 연결된 것입니다.

이미 EVPN을 쓰고 계시면 신청은 건너뛰고 위 확인만 해 주세요. 사용기간이 만료됐으면 나이스에서 다시 신청하셔야 합니다.

여는 말

챗봇에서 에이전트로

챗봇과 에이전트의 결정적인 차이는 결과물이 남는 위치임.

  • 챗봇: 대화창에 텍스트 답변을 보여주는 데서 멈춤. 공문 요약을 요청하면 화면에 요약글이 뜨지만, 그 내용을 한글 문서나 파일로 옮기는 일은 여전히 사용자 몫임.
  • 에이전트: 지정된 폴더에 직접 들어가 파일을 읽고, 문서를 편집하고, 결과 파일(.hwpx, .md, .csv 등)을 폴더에 저장함. 탐색기를 열어 보면 파일이 실제로 생성되어 있음.

이 차이가 학교 업무에서 중요한 이유:

  • 교사의 행정 업무는 화면 위의 대화로 끝나지 않음.
  • 공문을 열어 검토하고, 한글 서식을 채워 결재를 올리고, 나이스나 교무업무시스템에서 신청과 제출을 마쳐야 비로소 끝남.
  • 챗봇이 돕는 구간은 그 앞단의 초안 작성까지임. 실제 문서를 만들고 시스템을 조작하는 그다음 구간 전체를 다룸.

두 도구를 함께 쓰는 이유

이 과정에서는 Claude Desktop 앱(Code 탭)과 Claude Code CLI(터미널) 두 가지를 모두 셋업함. 같은 에이전트지만 실행 방법과 화면 조작이 다르고, 작업의 성격에 따라 편한 쪽이 갈림.

'Code'라는 이름 때문에 프로그래밍 전용 도구로 생각하기 쉽지만, 실제로는 컴퓨터로 할 수 있는 일상 업무 대부분을 처리함. 문서 작성, 파일 변환, 웹 검색, 시스템 설정 변경까지 코딩 지식 없이 자연어 대화만으로 제어함.

채팅, 코워크, 코드

Desktop 앱에는 세 가지 작업 방식이 있음. 권한 범위가 계단처럼 갈림.

  • 코드: 지정한 로컬 폴더의 파일을 직접 읽고 쓰고, 프로그램을 설치하고, 명령을 실행함.
  • 코워크: 코드에서 기능 몇 가지를 덜어낸 것임. 간단한 파일 생성과 문서 작업은 여기서도 됨.
  • 채팅: 코워크에서 로컬 권한을 덜어낸 것임. 대화만 주고받음.

이 과정에서는 모든 권한이 필요하므로 코드를 씀. 설정과 스킬이 저장되는 위치도 「코드와 터미널」과 「코워크와 채팅」 두 갈래로 나뉨.

Desktop 앱 화면 구조

좌측 사이드바를 위에서 아래로 훑으면 검색, 모드, 채팅 및 코워크, 코드, 새로 생성, 아티팩트, 사용자 지정, 더 많은 탐색 순으로 낭독됨. 메뉴 구성은 자주 바뀜. 이름이 다르게 읽히면 사이드바 전체를 한 번 훑어 확인함.

  1. 코드 진입: 사이드바에서 코드를 고르고 Enter. 라벨이 「코드 현재 페이지」로 바뀌면 진입한 것임.
  2. 프롬프트 편집창 이동: F2.
  3. 편집창에서 위로 올라가면: 다른 폴더 추가, 로컬 폴더.
  4. 편집창에서 아래로 내려가면: 작업을 설명하세요, 보내기, 편집 수락(권한 설정), 추가, 음성 입력, 모델, 노력, 컨텍스트 비율, 빠른 모드.

따라 하기 1: Desktop 앱 Code 탭 셋업

  1. Code 탭 이동: Claude Desktop 앱을 실행하고, 사이드바에서 코드를 눌러 이동.

  2. Git 설치 안내 확인: 처음 진입하면 Git 설치 안내가 뜸. Git 다운로드 버튼을 누름. - 나중에를 선택하면 Git 연동이 되지 않아 다음 단계가 막힘. 반드시 Git 다운로드를 선택함. - 아무 안내도 뜨지 않으면 먼저 폴더를 선택함(따라 하기 2의 1~2번). 폴더를 고른 뒤에 안내가 뜨는 경우가 있음. - 다른 에이전트(Codex 등)로 Git을 이미 설치했더라도 안내가 다시 뜰 수 있음. 그 에이전트를 켜 두었다면 아래 한 줄로 먼저 확인하는 편이 빠름.

    Claude를 쓰려는데 Git을 설치하라고 나옴. Git이 전역으로 설치되어 있는지 확인해 줘.

  3. Git 설치 진행: 내려받은 설치 파일(Git-x.x.x-64-bit.exe)을 실행하고, 설치 마법사의 모든 화면에서 기본 설정 그대로 Next 또는 Install을 눌러 끝까지 설치. - 설치 마법사에서 다음 버튼이 잡히지 않으면 안내의 다운로드 페이지 열기를 누름. 브라우저 창이 열리지 않는 경우가 있으므로, 다운로드 폴더로 직접 가서 내려받은 exe 파일을 실행함. - Git 설치를 마치기 전에는 프롬프트 입력창이 비활성이라 메시지를 보낼 수 없음. 입력창이 잠겨 있어도 정상임.

  4. 앱 완전 종료 후 재실행: Git 설치가 끝나면 앱을 완전히 닫고 다시 실행함. 재실행해야 입력창이 열림. 종료 방법은 아래 「조작이 먹히지 않을 때」와 같음.

  5. 설치 확인 요청: Code 탭으로 돌아와 하단 프롬프트 입력창에 확인을 요청.

    Git 설치를 마쳤는데 제대로 설치된 것인지 확인해 줘.

  6. PowerShell 실행 권한 허용: Claude가 설치 상태를 확인하려고 PowerShell 명령 실행 권한을 요청함. 거부, 한 번만 허용, 항상 허용 세 버튼 중 항상 허용을 선택. 이후 동일한 명령에는 다시 묻지 않음.

  7. 환경 변수 자동 설정: Git이 설치되어 있어도 Claude가 bash.exe 경로를 찾지 못하면 CLAUDE_CODE_GIT_BASH_PATH 환경 변수 설정 안내가 뜸. 보통 PowerShell로 설정하는 방법과 Windows 설정 창에서 직접 넣는 방법을 함께 제시함. 설정 창을 직접 열지 않고 입력창에 한 줄 적음.
    PowerShell로 환경 변수를 영구 설정하는 방법으로 네가 바로 해 줘.

Claude가 PowerShell 명령으로 환경 변수를 설정함. 안내에 붙은 번호는 그때그때 다르므로 번호 대신 방법을 말함. - 환경 변수 안내가 처음부터 뜨지 않으면 Claude가 이미 설정을 마친 것이므로 그대로 진행함. - 「현재 세션의 PATH에는 아직 반영되지 않았다」는 안내가 붙어도 그대로 둠. 새 대화를 열면 반영됨.

확인 방법: 프롬프트 입력창에 아무 문장이나 보내 답이 돌아오면 이 단계를 마친 것임.

앱을 최신으로 유지하기

Desktop 앱은 자주 업데이트됨. 구버전에서는 메뉴가 다르게 보이거나 권한 설정이 나타나지 않음. 처음 설치했다면 업데이트를 몇 번 반복해야 정상 화면이 나오기도 함.

  • 앱 안에서 검색으로 「업데이트」를 찾아 실행함.

새 대화 열기와 조작 복구

새 대화 열기

한 대화가 길어지면 새 대화로 갈아타는 편이 빠름. 설치와 설정을 마친 뒤에도 한 번 열어 둠.

  1. Ctrl+K를 누름.
  2. 가상 커서를 해제함. 해제하지 않으면 목록이 잡히지 않음.
  3. 위아래 방향키로 「새 채팅」, 「새 태스크」, 「새 코드 세션」을 훑고 새 코드 세션을 고름.

셋의 대응 관계는 앞의 세 가지 작업 방식과 같음. 새 채팅은 채팅, 새 태스크는 코워크, 새 코드 세션은 코드임. 영문으로 표시되면 New chat, New task, New code session으로 읽힘.

조작이 먹히지 않을 때

Ctrl+K를 눌렀는데 엉뚱한 라벨이 읽히거나, 가상 커서를 해제해도 방향키가 듣지 않는 경우가 있음. 아래 순서로 복구함.

  1. Esc를 여러 번 눌러 열려 있는 목록을 닫음.
  2. F2로 프롬프트 편집창으로 돌아감.
  3. F5로 화면을 새로 읽고 다시 탐색함.
  4. 그래도 라벨이 어긋나면 앱을 완전히 종료하고 다시 실행함.

앱 완전 종료 방법

Claude Desktop 앱은 작업 표시줄에 잡히지 않음. Alt+F4로 창을 닫아도 배경에 남아 있음. 작업 관리자로 끝냄.

  1. Ctrl+Shift+Esc로 작업 관리자를 엶.
  2. 가상 커서를 해제하고 목록을 내려가 Claude를 찾음.
  3. 팝업 키를 누르고 Alt+E(작업 끝내기)를 누름.
  4. Windows 키를 눌러 검색창에 「클로드」를 입력하고 실행함.

컴퓨터를 껐다 켜도 결과는 같음. 설치나 설정을 반영하려고 앱을 다시 켜야 할 때도 이 방법을 씀.

따라 하기 2: 폴더 지정과 첫 지시

에이전트는 지정한 폴더를 작업 범위로 삼음. 폴더를 지정해야 결과 파일이 정확한 위치에 생성됨.

  1. 작업 폴더 선택: 프롬프트 편집창에서 위로 올라가 로컬 폴더를 고르고 Enter. 파일 선택 대화상자가 열림.
  2. 연습 폴더 지정: 홈 디렉터리에 미리 만들어 둔 연습 폴더로 이동한 뒤 폴더 선택 버튼을 누름. 입력창 상단에 폴더 이름이 표시되면 지정 완료.
  3. 폴더 신뢰: 처음 여는 폴더면 신뢰를 묻는 화면이 뜸. 신뢰 버튼을 누름.

  4. 첫 지시 전송: 하단 입력창에 첫 지시를 입력하고 전송.

    이 폴더에 어떤 파일이 있는지 읽고 정리해 줘.

  5. 결과 확인: 연습 폴더에 넣어 둔 공문 PDF와 한글 문서를 인식하고 파일 이름과 형식을 설명하면 정상임.

샌드박스와 권한 관리

  • 작동 범위: 에이전트는 격리된 작업 영역(샌드박스) 안에서만 작동함. 지정된 작업 폴더 안에서는 자유롭게 문서를 읽고 씀.
  • 승인이 필요한 경우: 폴더 밖 시스템에 접근하거나 프로그램을 설치할 때. 승인 창이 뜨면 요청 내용을 확인하고 허용 여부를 결정함.
  • 자동 모드: 작업 폴더 안에서 반복적으로 뜨는 승인 창을 줄이는 설정임. 프롬프트 편집창에서 아래로 내려가면 나오는 편집 수락 풀다운 메뉴에서 자동을 선택하고, 확인 창에서 자동 모드 활성화를 누름. 계획 승인도 같은 방식으로 자동으로 바꿈. 지정한 작업 폴더 내부에만 적용되고 폴더 외부 시스템 영역에는 적용되지 않음.
  • 설정하지 않으면: 지시를 보낼 때마다 화면 최하단에 승인 요청 버튼이 계속 뜸.

참고: Pro 계정인데도 '자동' 모드가 메뉴에 보이지 않으면 앱이 구버전임.

파일 경로를 정확히 전달하는 요령

  • 방법: 파일 탐색기에서 대상 파일을 선택하고 Ctrl+Shift+C를 누르면 전체 경로가 클립보드에 복사됨. 이를 입력창에 붙여넣고 지시함.
  • 효과: 폴더에 파일이 여러 개일 때 엉뚱한 파일을 건드리지 않음.

작업 범위와 워크스페이스

챗봇을 쓸 때는 주고받은 내용이 전부 클라우드에 남았음. 에이전트는 작업 공간이 내 컴퓨터의 폴더로 내려옴. 폴더를 어떻게 나누어 두었는지가 곧 작업의 품질이 됨.

워크스페이스

용도가 다른 자료의 최상위 폴더를 워크스페이스라고 부름. 같은 폴더지만 작업의 큰 갈래를 가리킴.

  • 강사는 네 갈래를 씀. 홈 디렉터리의 개인 프로젝트 폴더, 학교 업무용 구글 드라이브, 노동조합 업무용 구글 드라이브, 개인 구글 드라이브.
  • 각자 학교용과 개인용 정도로 큰 갈래를 먼저 나누고, 그 안을 하위 폴더로 정리함.

홈 디렉터리

Windows의 홈 디렉터리는 C:\Users\<본인 계정 이름>임. 에이전트의 설정과 스킬이 모두 여기에 모임. 가끔 열어 훑으면 이 컴퓨터에 무엇이 깔려 있는지 알 수 있음.

구글 드라이브를 작업 범위로 쓰기

  • 데스크톱 앱을 설치한 경우: 클라우드의 파일이 로컬 파일이 되므로 에이전트가 그대로 읽고 씀.
  • 설치하지 않은 경우: 에이전트가 브라우저를 열어 드라이브 화면을 조작해야 함. 시간이 오래 걸리고 토큰을 많이 씀.

구글 드라이브 폴더를 워크스페이스로 잡으면 여러 컴퓨터가 같은 설정을 씀. 집에서 만든 규칙과 스킬이 학교 컴퓨터에서도 그대로 작동함.

  • 에이전트 사이에는 공유되지 않음. Codex로 설치한 스킬은 Claude가 쓰지 못함. 같은 스킬이라도 각 에이전트에서 한 번씩 설치함.
  • 전역 설치: 그냥 「스킬 설치해 줘」라고 하면 홈 디렉터리에 깔림. 이 컴퓨터 어디서나 쓰지만 다른 컴퓨터로는 따라오지 않음.
  • 워크스페이스 설치: 「[워크스페이스 이름] 워크스페이스에 스킬 설치해 줘」라고 하면 그 폴더 안에 .claude\skills가 생기고, 그 워크스페이스에서만 작동함. 구글 드라이브 폴더면 다른 컴퓨터에서도 그대로 씀.
  • 중복 관리: 에이전트는 작업 폴더와 그 상위 폴더의 .claude를 모두 훑음. 전역과 워크스페이스에 같은 스킬이 겹쳐 있으면 컨텍스트를 낭비하므로 한쪽을 지움.
  • 이름 앞의 점: .으로 시작하는 폴더는 목록 맨 위에 모임. 설정 폴더에 붙이는 오랜 관례임.

내가 무엇을 어디에 깔았는지 모르겠으면 에이전트에게 그대로 물어보면 됨.

지금 이 컴퓨터에 설치된 스킬이 무엇이고 각각 어디에 깔려 있는지 알려 줘.

규칙 파일 CLAUDE.md 만들기

폴더의 정체성을 적어 두는 파일임. 코드 저장소의 README와 같은 노릇을 함. 사람이 아니라 에이전트가 읽음.

만드는 법

작업 폴더를 선택한 상태에서 입력창에 보냄.

이 폴더의 파일들을 확인해서 CLAUDE.md를 만들어 줘.

슬래시 명령으로도 됨. /init을 입력하고 Enter를 누른 뒤, Tab으로 보내기 버튼까지 이동해야 전송되는 경우가 있음. 슬래시 명령은 자주 쓰는 지시를 짧게 줄여 둔 것임. 실무에서 손에 익는 것은 /init과 /compact 둘 정도임.

  • 폴더가 선택되지 않았으면 「CLAUDE.md를 만들 실제 프로젝트 폴더가 있으신가요?」라고 되물음. 폴더부터 선택함.
  • 「코드 프로젝트 폴더는 아니지만」이라는 문구가 답변에 붙는 경우가 있음. Claude Code가 코딩 도구로 설정되어 있어 코드 파일이 없는 폴더에 이렇게 적는 것임. 문서 작업용 폴더라고 CLAUDE.md에 기록되므로 그대로 두면 됨.

무엇이 달라지는가

폴더를 열면 CLAUDE.md의 내용이 자동으로 대화에 주입됨. 이 폴더가 무엇을 하는 폴더인지 매번 설명하지 않아도 됨.

수행평가 안내문 만들어 줘.

이 한 줄만 보내도 폴더의 맥락 안에서 작업함.

  • 짧은 작업 하나: 없어도 큰 차이가 없음.
  • 길고 복잡한 작업: 차이가 커짐. 에이전트가 혼자 일하는 시간이 길어질수록 시작점과 끝점을 정확히 알려 주는 값이 커짐.

폴더마다 두는 이유

워크스페이스 맨 위에 하나를 둠. 자주 작업하는 하위 폴더마다 하나씩 더 만듦.

  • 상위 폴더의 파일에는 전체에 통하는 일반적인 내용이 들어감.
  • 하위 폴더의 파일에는 그 프로젝트에만 해당하는 구체적인 내용이 들어감.
  • 계층 정리는 에이전트가 알아서 함. 어느 폴더에 필요한지만 말해 주면 됨.

폴더를 합치고 옮기고 지우고 나면 내용이 어긋남. 작업을 마칠 때 한 줄 보내 두면 됨.

CLAUDE.md 업데이트해 줘.
  • 다른 에이전트: Codex는 같은 파일을 AGENTS.md라는 이름으로 씀. 명시적으로 지시하지 않으면 만들지 않음.
  • 스킬과의 관계: 절차 지식까지 전부 CLAUDE.md에 적으면 파일이 끝없이 불어남. 특정한 절차만 따로 떼어 낸 것이 스킬임. 스킬은 절차를 성질로 삼는 마크다운 파일임.

에이전틱한 작업의 토대는 폴더 정리임. 프로젝트별로 폴더를 구분하고, 쓰지 않는 파일을 지우고, 각 폴더에 명찰을 붙임. 코딩에서는 한 프로젝트의 파일이 수천 개까지 늘어남. 그래서 오래전부터 이렇게 해 왔음.

마크다운 읽고 쓰기

에이전트가 만드는 문서는 대부분 마크다운(.md)임. CLAUDE.md도 마크다운이므로 여기서 읽는 법을 익힘.

메모장에서 구문 보기로 바꾸기

파일 탐색기에서 CLAUDE.md를 찾아 Enter를 누름. 마크다운 파일을 처음 여는 것이면 앱을 고르라는 화면이 뜨므로 메모장을 선택함.

Windows 11부터 메모장이 마크다운을 지원함. 기본값은 포맷 보기이고 제목은 크게, 굵게 표시한 글자는 굵게 보임. 센스리더가 아직 이 상태를 제대로 읽지 못함. 구문 보기로 바꿈.

  1. 메모장에서 Alt를 누름. 파일, 편집, 보기 메뉴가 뜸.
  2. 보기로 들어가 아래로 내려가면 마크다운이 있음. Enter.
  3. 포맷과 구문 중 구문을 고름.
  • 이 메뉴는 확장자가 .md인 파일을 열었을 때만 나타남. 영어로는 syntax임.
  • 구문 보기로 바꾼 뒤 방향키를 눌러도 아무것도 읽히지 않는 경우가 있음. Ctrl+T로 새 탭을 열었다가 닫으면 다시 읽힘.

  • 빠른 탐색: 찾기에서 #을 검색하면 제목 사이를 건너뛰며 이동함.
  • 목록 기호의 차이: 같은 뜻이지만 도구마다 습관이 다름. Gemini는 *로, Claude와 ChatGPT는 -로 내놓음.
  • 확장자만 다른 텍스트 파일: .txt 파일의 이름을 .md로 바꾸면 그대로 마크다운이 됨. HTML과 CSV도 같은 텍스트 기반 파일이며, 에이전트는 이런 형식을 가장 잘 다룸. 여기서 한글 문서와 워드 문서로 넘어가는 것도 어렵지 않음.

따라 하기 3: 터미널 CLI 환경 셋업

같은 Claude 에이전트를 터미널에서 가볍게 구동하는 절차임.

필요한 프로그램 설치

세 가지가 필요하며 설치는 에이전트에게 맡김. Desktop 앱 입력창에 그대로 보냄.

이 컴퓨터에 Windows 터미널이 설치돼 있는지 확인하고, PowerShell 7과 Claude Code CLI를 설치해 줘.
  • Windows 터미널: 이미 설치되어 있는 경우가 많음. 없으면 Microsoft Store에서 받음.
  • PowerShell 7: 대개 새로 설치해야 함.
  • Claude Code CLI: 대개 새로 설치해야 함. CLI는 command line interface, 명령 줄 인터페이스의 약자임.
  • 답이 「진행 중」에서 멈춘 것처럼 보이면 응답을 다시 훑고 한 번 더 물어 결과를 확인함.

터미널과 셸

  • 터미널: 애플리케이션임. Windows는 Windows 터미널, macOS는 터미널.
  • 셸: 터미널이 안에 띄우는 명령 해석기임. Windows는 PowerShell, macOS는 zsh.

터미널이 브라우저라면 셸은 그 안에 띄우는 사이트임. 하나의 터미널에서 여러 셸을 골라 씀. 화면 앞머리의 PS가 PowerShell의 약자임.

실행

  1. 작업 폴더 열기: 파일 탐색기에서 홈 디렉터리의 연습 폴더로 들어감.
  2. 포커스 해제: 방향키로 파일 목록을 훑었다면 포커스가 파일에 가 있음. 이 상태에서는 폴더 메뉴가 아니라 파일 메뉴가 열림. Ctrl+Space로 선택을 해제함.
  3. 터미널 열기: 팝업 키(또는 Shift+F10)를 눌러 컨텍스트 메뉴를 열고 터미널에서 열기를 선택. 「추가 옵션」 바로 위에 있음. 단축키는 Alt+T.

  4. Claude Code 실행: PowerShell 터미널이 열리면 다음을 입력하고 Enter.

    claude

  5. 첫 실행 설정: 처음이면 테마를 고르라는 화면이 나옴. 화면 색상에 대한 설정이므로 아무거나 골라도 무방함.

  6. 로그인 인증: 구독 로그인과 API 로그인 중 구독 로그인을 고름. 목록의 첫 번째임. 이어서 브라우저 인증 창이 열리므로 Claude 계정으로 로그인을 마치고 터미널로 돌아옴.
  7. 동작 확인: 프롬프트가 나타나면 간단한 지시를 보내 응답이 출력되는지 확인.
  • 탐색 방법: 터미널 화면은 키패드 리뷰로 훑음. 방향키로는 잡히지 않음.
  • 화면 언어: 첫 설정과 인증 화면은 영어로 나옴. 이 단계만 넘기면 이후는 한국어로 대화함.
  • 기본 위치: Windows 검색창에서 wt를 입력해 터미널을 열면 홈 디렉터리에서 시작함. 폴더에서 바로 여는 방법과 목적지가 다름.

터미널을 연 바로 그 폴더가 자동으로 작업 범위가 되므로, 앱처럼 폴더를 별도로 지정하지 않음.

  • 터미널 안에서 이동: cd ~로 홈 디렉터리, dir로 현재 폴더의 목록을 봄. DOS 시절의 명령과 비슷하지만 셸이 훨씬 더 복잡한 일을 함.

따라 하기 4: 스크린 리더 모드 켜기

  • 문제: 터미널 화면에는 테두리 선이나 진행 애니메이션 같은 장식 문자가 포함되어 있어, 키패드로 탐색할 때 불필요한 음성이 많이 낭독됨.
  • 해결: Claude Code가 이를 평문으로 전환해 주는 전용 스크린 리더 모드(axScreenReader)를 기본 제공함.

터미널 프롬프트에 한 줄 적음.

클로드 코드 설정에서 스크린 리더 모드 켜 줘.
  • 「클로드 코드 설정에서」를 빼지 않음. 이 말이 없으면 무엇을 켜라는 것인지 좁혀지지 않아, 곧바로 켜는 대신 무엇을 켤지 고르라는 목록이 뜸.
  • 고르라는 목록이 떴으면 목록에서 하나를 고르지 말고 위 문장을 그대로 다시 보냄.
  • 전역(Global) 설정으로 저장되므로, 한 번 켜 두면 터미널을 다시 열거나 다른 폴더에서 작업할 때도 유지됨.

확인 방법: 터미널을 닫고 검색창에 wt를 쳐서 다시 연 뒤 claude를 실행함. 시작 화면에 스크린 리더 모드가 켜져 있다는 안내가 나오면 적용된 것임. 키패드로 훑어 장식 문자가 사라졌는지도 함께 봄.

따라 하기 5: 두 도구로 동일한 폴더 다루기

터미널에서 폴더를 열고 claude를 실행하는 것은 앱에서 폴더를 고르는 것과 같음.

  1. 터미널에서 파일 목록 조회: 앱과 터미널이 모두 연습 폴더를 작업 범위로 잡은 상태에서, 터미널 프롬프트에 따라 하기 2와 동일한 지시를 보냄.

    이 폴더에 어떤 파일이 있는지 읽고 정리해 줘.

  2. 결과 비교: Desktop 앱에서 확인했던 것과 동일한 파일 목록이 출력되는지 확인.

  3. 터미널에서 파일 생성: 터미널에 다음과 같이 지시해 새 문서를 만듦.

    오늘 배운 핵심 내용을 세 줄로 정리해서 1회기 정리.md 파일로 저장해 줘.

  4. 탐색기에서 생성 파일 확인: 파일 탐색기에서 연습 폴더를 열어 1회기 정리.md가 실제로 생성되었는지 확인.

언제 무엇을 고르는가

두 도구는 동일한 로컬 파일 시스템을 제어함. 한쪽에서 만든 파일을 다른 쪽에서 즉시 읽고 편집하므로, 작업의 성격과 호흡에 맞추어 편한 쪽을 고르면 됨.

  • 터미널: 폴더를 찾아가 메모장처럼 가볍게 엶. 터미널을 띄운 바로 그 폴더만 작업 범위로 잡히므로, 워크스페이스 안쪽 깊은 하위 폴더의 파일 몇 개만 다룰 때 특히 유리함. 상위 폴더에서 열어 두고 「그 아래 어느 폴더의 파일을」이라고 설명하면 컨텍스트를 많이 쓰고 시간도 오래 걸림. 목적지 폴더에서 바로 열면 그 과정이 없음. 여러 터미널을 띄워 병렬로 작업할 수도 있음.
  • 앱: 구동과 업데이트에 시간이 걸리고 폴더도 매번 지정해야 함. 대신 아티팩트 미리보기와 사용량 점검이 됨. 웹 결과물을 눈으로 확인해야 하거나 하나의 프로젝트를 긴 호흡으로 다듬어 갈 때, 그리고 폴더 수가 적은 업무에 맞음.
  • 스크린 리더 조작: 앱은 웹 탐색 명령과 Tab 이동이 그대로 통하는 대신 편집창·버튼·텍스트 영역을 오갈 때 가상 커서 전환이 필요함. 터미널은 프롬프트 입력과 키패드 리뷰 탐색 중심이라 조작 체계가 단순한 대신 키패드 탐색에 익숙해야 함.

파일 탐색기를 빠르게 쓰기

파일 탐색기는 Windows 키+E로 엶. Windows에서 파일 시스템을 여는 앱이며 macOS의 Finder에 해당함.

  • 즐겨찾기 패널: 파일 목록에서 Shift+Tab을 누르면 최근에 작업한 폴더가 모인 패널로 이동함. 숫자 키로도 고름.
  • 자주 가는 폴더 고정: 폴더에서 팝업 키를 눌러 즐겨찾기에 고정을 선택함. 단축키는 Alt+Q. 학교 폴더, 개인 폴더처럼 매일 여는 곳을 고정해 두면 Shift+Tab 한 번으로 오감.
  • 탭으로 관리: Ctrl+T로 새 탭을 열고 Ctrl+F4로 닫음. 메모장도 같은 단축키를 씀. 창을 여러 개 띄우지 않으므로 Alt+Tab으로 오가야 할 대상이 줄어듦.
  • 가상 데스크톱: Ctrl+Windows 키+D로 추가하고 Ctrl+Windows 키+좌우 방향키로 전환함. 브라우저와 메신저를 한쪽에, 파일 탐색기와 터미널을 다른 쪽에 두면 창이 섞이지 않음.

터미널에서 Claude 다루기

터미널은 조작 체계가 단순한 대신 화면을 훑는 방법이 앱과 다름.

실행과 로그인

  1. 터미널 열기: 검색창에 wt를 입력해 Windows 터미널을 엶. PowerShell 7이 기본으로 뜸.
  2. Claude 실행: claude를 입력하고 Enter.
  3. 로그인: 로그인이 안 돼 있으면 숫자 1을 누르고 Enter. 브라우저가 열리면 계정을 고르고, 끝나면 터미널로 돌아옴.

스크린 리더 모드 확인

클로드 코드 설정에서 스크린 리더 모드 켜 줘.

확인 방법: 창을 닫고 wt, claude로 다시 열었을 때 스크린 리더 모드가 켜졌다는 안내가 먼저 뜸. 안 뜨면 안 켜진 것임.

입력창은 맨 아래에 있음

  • 채팅창과 같은 구조임. 입력창이 화면 맨 아래고, 그 가까이에 권한 모드 줄이 있음.
  • 커서가 입력창에 있어도 센스리더가 위쪽 내용을 읽고 있을 때가 있음. 입력하기 전에 아래 화살표를 두어 번 누름.

지난 응답은 키패드로 읽음

  • 위아래 화살표로는 읽히지 않음. Ctrl+넘패드 2로 맨 아래로 간 뒤 위로 올라가며 읽음. 맥에서도 같음.
  • 한 줄씩 위아래로만 오가면 되므로 익으면 단순함. 점자 디스플레이를 연결하면 훨씬 빠름.

선택지에는 누른 뒤 Enter

  • 숫자든 y든 n이든 누르고 Enter를 쳐야 넘어감. 스크린 리더 모드에서는 이것이 기본값임.
  • 입력이 안 먹은 것처럼 보이면 대개 Enter를 안 친 것임.

권한 모드는 Shift+Tab으로 바꿈

  • 누를 때마다 세 단계를 돌아감. 편집 승인, 플랜, 자동 순서임.
  • 자동으로 두면 승인 창에서 멈추지 않고 한 번에 끝까지 감. 오늘 실습은 자동으로 둠.

작업 중에는 진행 줄이 계속 낭독됨

작업 시간이 갱신되면서 같은 줄을 되풀이해 읽음. 터미널에서 가장 성가신 점임. 대처는 셋임.

  • 지시를 보낸 뒤 다른 창으로 포커스를 옮기고 끝나기를 기다림.
  • 점자 디스플레이를 연결함. 소리 없이 마지막 줄만 표시됨.
  • 음성만 잠시 끔.

중간 과정이 영어로 길게 흐르는 것은 정상임

무엇을 하는지 다 보여 주는 설계임. 요약만 듣고 넘어가면 되고, 상세를 확인해야 할 때만 키패드로 올라가 읽음.

창을 하나 더 여는 법

  • Ctrl+T로 새 탭을 엶. 안 되면 Ctrl+Shift+숫자 1.
  • 둘 다 안 되면 처음처럼 wt로 새 창을 엶. 메모장처럼 얼마든지 열림.
  • 대화를 새로 시작하려면 exit로 나갔다가 claude를 다시 실행함.

설치가 실패할 때

이 스킬은 Node.js 위에서 돎. Node.js는 음성과 무관한 기본 개발 도구인데, 이것이 없으면 스킬이 서지 않음. 도구 이름을 하나씩 짚어 설치하지 않고 통째로 맡김.

이런 개발 환경 설정은 내가 잘 모르니, 필요한 도구와 라이브러리는 네가 알아서 설치해 줘.

모른다고 밝히는 것이 요령임. 에이전트가 사용자를 개발자로 보면 단계마다 승인을 물으며 멈춤. 모른다고 하면 알아서 처리하고 설명도 쉬운 말로 바꿔 줌.

  • skills-for-the-blind: 그 자체가 하나의 스킬임. 안에 기능은 없고 멤버 다섯 개를 차례로 설치하는 일만 함. 다섯은 각각 독립된 저장소라 필요한 것 하나만 주소로 지목해 따로 설치해도 됨.
  • school-work-automation: 한 저장소 안에 스킬 셋이 들어 있음. 저장소를 설치하면 셋이 함께 들어옴.

설치와 활성화를 나누지 않음

스킬은 켜고 끄는 것이 아님. 설치하면 그때부터 이름을 불러 쓸 수 있음. 활성화 절차를 따로 찾지 않아도 됨.

스킬마다 필요한 도구가 다름

설치가 끝나도 스킬을 실제로 돌릴 때 필요한 도구가 따로 있음. 문서 파싱과 한글 자동화가 특히 그럼. 쓰려는 스킬이 정해지면 먼저 진단시킴.

이 스킬을 쓰는 데 필요한 도구가 설치돼 있는지 진단하고, 없는 것은 설치해 줘.
  • 범용 도구는 전역 설치를 요청함. 기본값은 지금 폴더에만 설치하는 것이라, 다른 폴더에서 열면 없다고 나옴.
  • 「우회하겠다」는 응답을 그냥 넘기지 않음. 무엇이 막혀 우회하는지 끝까지 확인함. 학교 컴퓨터의 보안 설정 때문일 수도 있고 도구 하나가 빠진 것일 수도 있는데, 원인을 가리지 않으면 다음에 같은 곳에서 또 막힘.

무엇을 쓸 수 있는지 한 번 훑음

school-work-automation 번들에 어떤 스킬이 있고, 각 스킬로 무엇을 자동화할 수 있는지 알려 줘.

스킬은 자동으로 갱신되지 않음

공개된 스킬이 개선돼도 이미 설치한 것에는 반영되지 않음. 갱신하려면 다시 설치함.

고쳐 쓸 것은 이름을 바꿔 둠

한 번 받은 스킬은 사용자의 파일임. 제공자에게 묶이지 않으므로 내용을 열어 고쳐도 되고 자기 업무에 맞게 바꿔 써도 됨. 다만 원래 이름 그대로 고쳐 두면 다시 설치할 때 덮어써져 사라짐. 설치가 스킬 이름으로 자리를 잡기 때문임.

  • 폴더 이름과 SKILL.md 첫머리의 name을 함께 바꿈. 하나만 바꾸면 같은 이름의 스킬이 둘이 되어 에이전트가 어느 쪽을 부를지 가리지 못함.
  • description도 자기 용도에 맞게 고침. 에이전트는 이 줄을 읽고 스킬을 고름.
  • 이름을 바꾼 뒤로는 원본이 개선돼도 따라오지 않음. 갱신을 계속 받고 싶으면 원본은 그대로 두고, 바꾸고 싶은 것을 규칙 파일(CLAUDE.md)에 적어 두는 방법도 있음.

이 작업도 말로 시킴. 대괄호는 자기가 붙일 이름으로 바꿔 넣음.

docparse 스킬을 복사해서 [새 이름]이라는 별도 스킬로 만들어 줘. 폴더 이름과 SKILL.md의 name, description을 그 이름에 맞게 바꿔 줘.

출처를 모르는 스킬은 설치하지 않음

스킬은 에이전트에게 절차를 지시하는 파일이므로 그 안에 적힌 내용이 곧 에이전트가 할 일이 됨. 출처를 모르는 스킬을 설치하면 무엇을 시키는지 모르는 채로 내 컴퓨터의 파일을 맡기게 되고, 정보 유출 위험이 있음.

오늘 설치한 두 번들은 강사가 만들어 공개한 것이고 소스가 전부 열려 있음. 다른 스킬을 설치할 때도 저장소를 열어 SKILL.md를 먼저 읽는 습관을 붙임.

막혔을 때의 증상 둘

  • 접속을 지시했는데 화면에 터미널만 있고 크롬 창이 아예 뜨지 않음.

  • 확장이 켜져 있다는 것과 로그인돼 있다는 것은 다름. 크롬 확장 목록에 켜짐으로 나와도 로그인을 안 했으면 에이전트는 확장이 없는 것으로 봄. 설치하라는 말이 되풀이되면 로그인부터 확인함.
  • 웹 스토어 페이지는 패널이 아님. 툴바 항목을 눌렀는데 뜬 화면의 주소가 chromewebstore로 시작하면 그것은 설치 안내 페이지임. 패널에는 입력창과 로그인 버튼이 있음.
  • 툴바 고정이 먼저임. 고정을 건너뛰면 F6 경로도 Alt 경로도 헛돌게 됨.
  • 확장 로그인은 사람이 함. 다른 에이전트에게 대신 시켜도 되지 않음. 확장의 로그인 화면은 에이전트가 잡을 수 있는 대상이 아님.

따라 하기 9: EVPN 접속과 업무포털 로그인

학교 밖에서 내부 업무 시스템에 들어가려면 교육청 원격업무지원서비스(EVPN)를 먼저 거쳐야 함.

  • EVPN이 필요한 시스템: 업무포털과 K-에듀파인. 연결 없이는 서버 응답 자체가 없어, 화면이 뜨지 않고 그냥 멈춘 것처럼 보임.
  • EVPN 없이도 되는 시스템: 나이스. 공인망에서도 서버가 응답함. 다만 업무포털을 거친 자동 로그인은 쓸 수 없어 나이스 자체 인증서 로그인을 해야 함.
  1. 웹 로그인: 브라우저로 자기 교육청 EVPN 주소에 접속해 나이스 아이디와 VPN 전용 비밀번호로 로그인. 비밀번호는 본인이 직접 넣음.
  2. 설치 안내 팝업 닫기: 첫 화면에 설치 안내 팝업이 떠 있으면 닫음. 이 팝업은 마우스 클릭을 가로채지만 키보드 탐색에는 영향이 없음.
  3. 클라이언트 로그인: 상단 Run VPN 버튼을 누르면 별도의 클라이언트 로그인 창이 뜸. 웹 로그인과는 다른 2차 인증이며, 같은 아이디와 VPN 비밀번호로 로그인하면 터널이 연결됨.
  4. 연결 확인: 페이지 상단 상태의 Installed, Running, Connected가 모두 Yes가 되면 연결된 것임.
  5. 업무포털 로그인: 자기 교육청 업무포털 주소로 이동해 인증서로 로그인. 인증서 비밀번호는 언제나 본인이 직접 넣음. 이 입력은 자동화하지 않음.

에이전트에게 접속부터 맡겨도 됨. 로그인 창에서는 알아서 멈추므로 비밀번호만 직접 넣으면 됨.

EVPN에 접속하고 업무포털까지 진입해 줘. 비밀번호는 내가 넣을게.

알아 둘 함정 두 가지

  • Installed No가 미설치를 뜻하지 않음: 클라이언트가 설치돼 있어도 실행 중이 아니면 No로 표시됨. Run VPN으로 클라이언트를 호출하면 Yes로 바뀜.
  • 터널이 오래 유지되지 않음: 연결 12분 뒤에 끊긴 사례가 있음. 작업 중 화면이 갑자기 응답하지 않으면 EVPN이 끊긴 것부터 의심하고, 웹 재로그인과 Run VPN을 다시 밟음.

따라 하기 10: 나이스 접속

로그인까지는 사람이 했음. 여기서부터 화면을 읽고 누르는 일을 에이전트에게 맡김.

  1. 브라우저 연결 확인: 따라 하기 8의 연결 확인을 마쳤는지 먼저 봄. 크롬 창이 뜨지 않으면 나이스가 아니라 확장 문제임.

    크롬 창을 띄우고 지금 열려 있는 탭을 읽어 줘.

  2. 진입 지시: 입력창에 전송.

    나이스 스킬로 업무포털에서 나이스에 들어가 줘. 로그인은 내가 이미 해 뒀어.

  3. 자동 진입 진행: 에이전트가 업무포털 메인의 공지 팝업을 닫고 [나이스] 링크를 눌러 새 탭으로 진입함. 로그인 정보는 자동으로 넘어감.

  4. 화면 판독 요청: 나이스 메인이 뜨면 화면을 읽게 함.

    지금 화면에 무엇이 있는지 알려 줘. 좌측 메뉴에 어떤 항목이 있어?

  5. 메뉴 확인: 좌측 기본 메뉴에 복무, 외부활동, 승인사항 같은 항목이 잡히는지 확인함.

확인할 지점은 화면에 들어갔다는 사실이 아니라 화면을 에이전트가 읽어 준다는 사실임. 무엇이 어디에 있는지 스스로 훑지 않아도 되고, 필요한 메뉴를 이름으로 물어 찾아갈 수 있음.

따라 하기 11: K-에듀파인 접속

  1. 진입과 목록 판독 지시: 업무포털로 돌아가 전송.

    K-에듀파인 스킬로 K-에듀파인에 들어가서 결재대기 목록을 읽어 줘.

  2. 자동 진입 진행: 업무포털 상단의 [K-에듀파인]을 누르면 새 탭으로 진입함. 보안 프로그램 안내 페이지가 먼저 뜨면 에이전트가 넘김.

  3. 목록 확인: 문서관리 > 결재 > 결재대기로 이동해 목록을 읽음. 문서 제목, 기안 부서, 긴급 여부, 첨부 건수가 나옴.
  4. 건수 대조: 결재 대기 건수는 업무포털 메인의 K-에듀파인 문서함 위젯으로도 확인됨. 처리 전후를 대조할 때 편함.

  5. 문서 열기 지시: 목록에서 한 건을 골라 전송.

    첫 번째 문서를 열어 줘.

  6. 화면 무변화가 정상: 문서를 열어도 브라우저 화면에는 아무 변화가 없음. 새 탭도 생기지 않음. 결재 문서 창은 브라우저 밖의 별도 프로그램 창으로 뜨기 때문임. 화면이 그대로라고 실패로 오해해 다시 누르면 누른 횟수만큼 창이 중복 생성되므로 반복 클릭하지 않음.

  7. 창 확인 지시: 창이 떴는지는 에이전트에게 확인시킴.

    결재 문서 창이 떴는지 확인하고, 창 안의 문서 제목을 읽어 줘.

  8. 판독 확인: PowerShell 브리지가 창 안을 잡아 제목과 본문 일부를 읽어 주면 창을 읽는 데까지 간 것임.

화면 변화로 성공 여부를 판단할 수 없으므로, 조작 결과는 언제나 에이전트에게 물어 확인함.

따라 하기 12: 교데통 접속

교데통은 K-에듀파인의 자료집계를 대체한 데이터 취합 플랫폼임.

  • 주소가 두 개임: www.edmgr.kr은 일반 공개 포털이고, 데이터취합 메뉴가 있는 것은 시도 서브도메인이 붙은 업무용 주소 하나뿐임. 공개 포털로 들어가면 아무리 뒤져도 제출 화면이 없음.

  1. 진입 지시: 업무포털 상단 메뉴의 [교데통]으로 들어감. 창 폭이 좁으면 메뉴가 잘려 보이므로 에이전트에게 링크를 찾게 하는 편이 빠름.

    교데통 스킬로 교데통에 들어가서 제출자료 화면을 열어 줘.

  2. 팝업 두 겹 닫기: 교데통 메인에 처음 들어가면 공지 팝업이 두 겹으로 뜸. 안쪽부터 닫음. 팝업 하단의 "다시 열지 않음" 체크는 임의로 켜지 않음.

  3. 메뉴 이동: 상단 메뉴에서 데이터취합 > 제출자료로 이동.

  4. 화면 구조 판독 요청: 전송.

    지금 화면의 탭과 각 탭의 건수를 알려 줘.

  5. 탭 확인: 기관접수대기, 내담당, 제출완료, 종료, 강제종료 다섯 탭과 각각의 건수가 나오면 정상임.

목록이 비어 있어도 요청이 없는 것은 아님

기관접수대기 목록은 기관 안의 전체 직원에게 보이고, 누군가 접수하면 나머지 사람의 목록에서 사라짐. 목록이 비어 있다고 해서 학교에 온 취합 요청이 없다고 단정하지 않음. 건수가 많으면 요청자료명에 키워드를 넣고 조회하는 편이 빠름.

세 시스템 자동화의 경계

"나이스나 K-에듀파인은 자동화가 안 된다"는 말이 오래 통용됐음. 정확히 말하면 막혀 있는 것이 아니라 화면마다 우회가 필요함. 그 우회를 하나씩 알아내는 데 시간이 들 뿐이고, 알아낸 것을 스킬에 적어 두면 다음부터는 그 시간이 들지 않음.

되는 범위와 멈추는 지점은 다음과 같음.

  • 읽기와 조회는 폭넓게 됨: 목록 읽기, 상세 화면 읽기, 현황 조회, 문서 저장.
  • 폼 채우기와 검증도 됨: 복무 신청 화면의 항목을 채우고 계산된 값이 맞는지 확인하는 데까지.
  • 비가역 조작은 사람이 확인함: 상신, 문서처리, 제출, 발송은 한 번 누르면 되돌리기 어려움. 자동화는 확정 버튼 앞에서 멈추고 무엇을 하려는지 요약해 보고함.
  • 자격증명은 자동화하지 않음: 인증서 비밀번호와 VPN 비밀번호는 언제나 본인이 직접 넣음.

뒤의 두 항목은 기술의 한계가 아니라 정해 둔 선임.
